# Capture evening

Tickets: $ARGUMENTS. Rules for every step: [`docs/agents/workflow.md`](../../../docs/agents/workflow.md). Each step
ends when its criterion holds; report it before the next.

Hard rules, throughout:

- Commit only code, notes and raw sources with no game text and no local path (`AGENTS.md` rules 4 and 6).
- Hook `.text1` only in Debug, opt-in listeners (ADR 0010).
- Stop only processes you started. Check every push's own exit code.
- While the maintainer plays, run no build, check or deploy: `bash scripts/check/check-status.sh` shows what is running.

## 1. Evening issue

Read each ticket and its comments (`gh issue view <n> --comments`). Done when every ticket is `needs-game` and its play
steps are listed. Open one issue, `ready-for-human`, titled "Capture evening <n>", listing them, with a `This was
generated by AI.` first line as in `docs/agents/issue-tracker.md`. Link each ticket as blocked by it, natively. Done when
`gh issue view <n> --json blockedBy` shows the evening issue on every ticket.

## 2. Prep the kit

Branch `capture-kit-<n>` from the latest kit branch (`git branch -r | grep capture`), or `origin/main` if none, and
comment the base on the evening issue. One or two background agents (Opus, hook work) build Debug-only, opt-in
listeners, one area each. Each follows the hook section of `workflow.md`: it runs `security-reviewer` in the foreground,
commits with the stamp and pushes to the kit branch. A merge of `main` or of another kit half gets its own review. Done
when every listener is committed, pushed, stamped and reviewed.

## 3. Checklist

Post one checklist on the evening issue from [`checklist-template.md`](checklist-template.md). Done when it names each
opt-in file with its tickets, the expected `hooks n/m`, the order of play and what to narrate, and reads aloud in a
couple of minutes.

## 4. Session

When the maintainer says ready, and with the game closed, follow
[run a game session](../../../docs/contributors/how-to/run-a-game-session.md): one
`pwsh scripts/dev/session.ps1 run -Seconds <longer than the evening> -OptIn <names> -SaveLog <folder outside the repo>`,
in the background, since it lasts until the game exits. Done when the output shows `hooks n/m` as expected with no
`skipped: opt-in` or failed listener. Tell the maintainer to start OBS and narrate, and to quit the game when done. Fix
a missing listener before they play.

## 5. Analysis

Done when the session's last line is `ok: ...`: it saved the logs to the `-SaveLog` folder and removed the opt-ins. Transcribe the narration with the `watch` skill
(local engine). Compute the offset: the mod's Ready time in the log minus the recording's start; pass it as `--offset` to
`tools/Metaphor.SessionLog` ([how-to](../../../docs/contributors/how-to/deploy-a-dev-build.md#summarise-a-log)).

One analysis agent per area (Sonnet for inventories, Opus for RE), each running `tools/Metaphor.SessionLog` over its window and
writing raw sources under `docs/raw-sources/` with the header from its README, no game text. Each opens a docs PR with
`gh pr merge <n> --auto`, then comments on its tickets. Done when every ticket has a raw source and a comment.

## 6. Close out

Close each ticket the evidence answers. Split what it doesn't into one follow-up spike, and move the blocking edges to
it. Comment the results on the evening issue and close it. Done when no answered ticket stays open and no open ticket
stays blocked by a closed evening issue.
